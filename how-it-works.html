How ShieldVault works

ShieldVault checks text locally before risky content leaves the browser.

Hard blocks

When ShieldVault detects a secret, token, credential, private key, or risky large paste, it prevents the action and clears the field before the content can be submitted.

Soft flags

Optional Reputation Guard can pause heated messages, late-night posts, and tense phrasing so you can edit before sending.

Local-only model

Detection without possession.

Secret and message checks run with local patterns in your browser. Activity history stores metadata only: time, site, category/vector, and detector names.

Fake examples

Use fake values when testing. ShieldVault should treat examples like these as risky without exposing a real credential.

sk-test-1234567890abcdef1234567890abcdef ghp_000000000000000000000000000000000000

Known limits

  • Pattern detection can miss secrets in unusual formats.
  • Some sites handle editors in ways that may require fallback blocking.
  • Soft flags are simple local pattern checks, not an AI judgment.
  • Undo / allow once is temporary and scoped to the same site, field, and content hash.
